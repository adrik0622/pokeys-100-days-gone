# Unattended v2 implementation sweep

Started 2026-10-18, user-approved [SC-004](SCOPE_CHANGES.md). A-Life + Jeem is the selected direction; Bandits is a retained rollback fixture, not a co-owner. Work locally, commit significant steps, preserve old worlds and raw evidence. A blocker on one seam does not prevent independent progress. No release/capacity acceptance is implied.

## Order and decisions

1. **NPC foundation:** pin selected ownership; create a fresh v2 composition with controlled A-Life/Jeem features, ordinary-player contact/consequence and presentation compatibility. Keep previous Henry/Delbert worlds unchanged. Inspect native faction import/protection/reputation boundaries before writing a parallel system.
2. **Supply/pressure owner:** inspect exact Military Drop dependencies and authoritative request/trust/zombie lifecycle against existing Horde Nights drop path. Choose one drop owner; disable overlapping drops. Start with a tiny bounded fixture, no client acknowledgement treated as physical proof.
3. **Contracts and variety:** inspect The Mission and Random Zeds. Configure/try only useful modules. Prefer native zombie variation if a randomizer conflicts with NPC shells; no Synapse/blanket Java policy. Do not add a generic economy or workers simply because available.
4. **Connected player choices:** build one shortage → choose/deliver/divert → persistent service/relationship/world consequence slice, integrating demonstrated owners. Keep optional calibration useful but nonmandatory. Original adapters only for evidenced gaps; preserve v1 ledger under its own namespace.
5. **Recovery and handoff:** fresh process restarts, resource samples and focused tests. Package original development files only after a clean commit. Leave disposable clients/server stopped and diagnostics off. Prepare an illustrated local report/catalog with evidence labels, diagrams, screenshots, exact knobs/defaults/tweaks and unresolved choices.

## Decision rules

- One physical NPC owner (A-Life), one source for each reputation balance, one drop fulfillment authority, one horde routing owner. No Subscribe All stack or competing director.
- Choose by player-visible causality, exact engine/MP behavior, runtime cost and lifetime maintenance. Source claims, mocked tests and engine observations remain separate.
- Consequence is not an anti-PK policy. Neutral/hostile/defensive/unknown events are distinct; unknown attribution must not manufacture sanctions or rewards.
- Counts/timings in experiments are not release performance budgets. Use fresh processes and one rendered client first; no 4–8 rendered-client capacity proxy.
- Input needed only for genuinely material policy/deployment decisions or unavailable credentials/permissions. Record action, blocker and independent alternatives; do not wait idle.

Progress/results belong in PROGRESS, source/runtime cards and the final v2 report. This plan is an implementation sequence, not a promise all candidates will be adopted or v2 accepted by morning.
